# 文章 RSS 排除开关设计

## 目标

让管理员可以将单篇公开文章排除在 RSS 之外，同时文章仍保持在网站中公开可访问。该能力只适用于「文章（Posts）」。

## 已确认的交互

- 文章编辑页新增「不展示在 RSS」开关，默认关闭。
- 桌面端将该开关放在「时间自定义」右侧；移动端将其放在「时间自定义」下方。
- 文章公开且开关开启时：
  - 后台文章列表的桌面表格「可见性」列显示绿色的「公开 (不RSS)」。
  - 后台文章列表的移动卡片可见性标签同样显示绿色的「公开 (不RSS)」。
- 除上述两处文章列表状态外，不展示「不 RSS」标记：编辑页顶部、前台页面与其他内容类型仍只显示普通「公开」。

## 数据与接口

- 仅为 `posts` 表新增 `exclude_from_rss` 布尔列，非空、默认 `false`。
- Posts 的创建、更新、列表和详情接口读写并返回该字段；日记、碎碎念和文摘接口不增加该字段。
- 现有文章不做行为变更，迁移后的默认值均为 `false`。
- 导入与导出保留该字段，避免备份恢复后丢失 RSS 排除设置。

## RSS 行为

- 网站公开文章查询、文章详情页、搜索和订阅通知维持现有逻辑；开关只影响文章 RSS。
- 文章 RSS 在数据库查询阶段排除 `exclude_from_rss = true` 的文章，再应用 RSS 条数限制，保证在较新的文章被排除后仍可返回最新的可展示文章。
- 私密文章仍遵循现有规则，不会进入 RSS。

## 前端实现

- 为共享的发布时间区域增加可选的附加开关槽位，仅文章编辑页传入「不展示在 RSS」开关，避免日记等编辑页出现该控件。
- 使用响应式布局确保桌面端与移动端的指定位置一致。
- 文章列表把 RSS 排除状态转换为展示用状态标签；通用状态组件保留既有的「公开」语义，避免影响其他列表。

## 验证范围

- 后端：Posts API 的默认值、创建、更新、读取、导入导出；私密与 RSS 排除文章均不出现在文章 RSS；RSS 在排除靠前文章后仍补足可展示条目。
- 前端：开关默认关闭、保存载荷与回填、桌面表格和移动卡片的「公开 (不RSS)」标签，以及非文章页面不出现该开关。
- 生成：更新 OpenAPI 与 API 客户端生成物，并运行生成一致性检查。
