# 文摘详情弹窗体验设计

**日期：** 2026-07-31
**状态：** 已确认

## 目标

修复文摘详情弹窗在移动端的布局与可用性问题，适度增加桌面端阅读宽度，让正文按项目的完整 Markdown 能力渲染，并把评论交互固定在弹窗底部。

## 范围与交互

- 弹窗采用纵向三段布局：固定的元信息区、可滚动的正文区、固定的评论操作区。
- 桌面端扩大阅读宽度；移动端使用贴合视口与安全区的高度和内边距，保证关闭与评论操作始终可触达。
- 文摘正文复用现有 `MarkdownRenderer`，获得 GFM、公式、代码高亮、图片、链接预览和项目 Markdown 指令支持。列表卡片继续只显示文本摘要。
- 底部常驻“查看评论 / 收起评论”控制，不随着正文滚动。
- 打开评论后，从底部展开评论抽屉：
  - 正文保留独立滚动位置；
  - 评论列表在抽屉中独立滚动；
  - 评论输入框固定在评论抽屉底部。
- 正文和评论列表均使用细窄、低对比度的滚动位置指示条；滚动或悬停时略微增强，静止时弱化。移动端不干扰系统原生滚动与安全区。

## 实现边界

- 复用现有 `MarkdownRenderer`、`CommentSection`、`WalineSurface` 与主题变量，不新增 Markdown 依赖。
- 为弹窗内评论区域提供紧凑的布局变体，避免影响文章页、日记页和留言板的既有评论体验。
- 保持现有评论懒加载、关闭、预览、加载与错误状态。

## 验证要点

- 为弹窗结构和渲染器选择补充前端回归测试。
- 在窄屏和桌面视口验证：正文、评论列表分别滚动；底部控制与评论输入框保持固定；内容不被底部安全区遮挡。
- 执行受影响前端测试、类型检查、代码检查与生产构建。
