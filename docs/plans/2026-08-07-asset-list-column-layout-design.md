# 资源列表列宽修复设计

## 目标

恢复资源管理页面原先舒展、易扫读的列表布局，避免长文件名把分类、资源范围、可见性和文件大小等短字段挤成多行，同时保留本次新增的四类资源入口和现有操作能力。

## 根因

- 资源列表当前使用浏览器自动表格布局，所有列都没有稳定的宽度约束。
- 旧数据中的文件名较短、备注内容较多，浏览器当时恰好分配出了较均衡的列宽。
- 本次资源整理后，列表中出现更长且不易断行的文件名，同时不少备注为空。文件名列因此取得过多空间，后面的短字段被压缩成两行。
- 这不是资源范围列本身过多，而是表格布局依赖每一页具体数据，导致相同页面在不同数据下呈现不稳定。

## 方案选择

采用稳定列宽规则，不只单独限制文件名：

- 文件名和备注作为主要内容列，占用可伸缩的主要空间。
- 文件名单行显示，超出列宽时显示省略号，并通过悬停标题提供完整名称。
- 备注同样保持单行省略，避免备注内容重新影响整张表的列宽。
- 分类、资源范围、可见性、文件大小、链接和操作列设置合理的最小宽度并禁止换行。
- 文件预览、复制链接、编辑、删除和展开详情的行为保持不变。
- 当管理区宽度不足以容纳稳定列宽时，复用现有表格横向滚动能力，不再把短字段拆成多行。

没有采用“只限制文件名”的方案，因为备注或分类内容变化后仍可能再次挤压其他列；也不把表格重写成 CSS Grid，因为现有 `DataTable` 已支持逐列样式，重写会扩大不必要的影响范围。

## 实现边界

- 仅修改资源列表的列定义及对应前端回归测试。
- 复用 `DataTable` 已有的列 `className` 和横向滚动，不新增表格组件或全局样式。
- 不修改资源接口、资源迁移、分类规则、上传和编辑逻辑。
- OSS 同步记录列表保持现状，本次只处理截图中出现问题的资源文件列表。

## 验证

- 测试长文件名具备单行截断和完整名称提示。
- 测试短字段列具备稳定最小宽度和禁止换行规则。
- 运行资源页面定向测试和管理端类型、构建检查。
- 在真实浏览器中分别检查桌面宽度和较窄管理区：桌面布局应接近旧截图，窄窗口应横向滚动而不是拆散短字段。
